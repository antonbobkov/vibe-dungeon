# UNDERVAULT — 05: Data Formats

Concrete file formats. TypeScript-style type definitions are normative; JSON examples are
illustrative. All files are JSON with UTF-8, committed to the repo (text only).

## 1. Level files — `levels/f1.json` … `levels/f4.json`

The ASCII maps from 03-levels.md are embedded verbatim; the loader parses them against
the legend (03 §1.2). Tables from 03-levels transcribe into the sibling fields.

```ts
interface FloorFile {
  id: 'f1' | 'f2' | 'f3' | 'f4';
  name: string;                      // "The Gatehouse"
  rooms: Room[];
  doors: Door[];
  wiring: Wire[];
}

interface Room {
  id: string;                        // "R1"
  name: string;                      // "Entry Hall"
  map: string[];                     // one string per row, exactly as in 03-levels
  combatSeal?: boolean;
  enemies?:  { marker: string; type: 'skel_sword'|'skel_axe'|'zombie'|'wisp';
               drop?: PickupName }[];          // marker = the digit used in `map`
  traps?:    { at: [number, number]; kind: 'spike'|'arrow'|'flame_down'|'flame_right'|'flame_left';
               period?: number; offset?: number; alwaysOn?: boolean }[];
  props?:    { at: [number, number]; kind: 'chest'|'mini_chest'|'crate_wood'|'crate_steel';
               contents?: PickupName[];         // chests
               drop?: PickupName }[];           // crates
  torchGroups?: { id: string; members: [number, number][]; window?: number }[];
  waves?:    { type: EnemyType; at: [number, number]; drop?: PickupName }[][];
  decor?:    { at: [number, number]; art: string }[];   // art = AG ref, e.g. "A(4,6)" or "flag"
}

interface Door {
  id: string;                        // "d3"
  type: 'normal' | 'gap' | 'silver' | 'gold' | 'puzzle';
  a: { room: string; cells: [number, number][] };
  b: { room: string; cells: [number, number][] };
}

interface Wire {
  trigger: { kind: 'torch_group'; group: string }
          | { kind: 'room_clear'; room: string }
          | { kind: 'chest_open'; room: string; at: [number, number] };
  effects: ({ kind: 'open_door'; door: string }
          | { kind: 'spawn'; room: string; at: [number, number]; pickup: PickupName }
          | { kind: 'victory' })[];
}

type PickupName = 'coin'|'red_small'|'red_large'|'blue_small'|'blue_large'
                | 'silver_key'|'gold_key';
```

Redundancy rule: information that the map already carries (spike/coin/crate positions
etc.) still appears in the tables **only where 03-levels lists parameters** (trap
periods, crate drops, chest contents). The loader takes positions from the map and
parameters from the tables, and errors on any mismatch (a table entry whose `at` doesn't
hold the matching symbol, or a parameterised symbol with no table entry). Simple pickups
(`c h H b B k K`) and default-parameter traps need no table entry.

## 2. Tile metadata — `src/assets/packA.ts`

Generated by hand once from ASSET_GUIDE §3.1/§3.5 tables (M0). One record per used tile
/ animation:

```ts
interface TileDef  { id: string; sheet: 'tileset'|'character'; col: number; row: number;
                     kind: 'terrain'|'alpha_prop'|'black_backed'; }
interface AnimDef  { id: string; dir: string;                  // folder under art_assets
                     frames: string[];                          // file names, in PLAY order
                     frameTicks: number; loop: boolean;
                     frameSize?: [number, number]; }            // when not 16×16
```

The `frames` arrays must encode the corrected play orders from AG §3.5 (e.g. peaks
`3,4,2,1`; flamethrower `4,3,1,2`; arrow `2,3,4,1`). A unit test locks these.

## 3. Input recording — replays and macros

### 3.1 Replay file — `tests/replay/*.replay.json`

```ts
interface Replay {
  floor: FloorFile['id'];
  start: { hp: number; treasure: number; deaths: number };  // state on floor entry
  inputs: string;              // base64 of one byte per tick, bits per 01-mechanics §2
  asserts: { tick: number; expect: Partial<{
      room: string; hp: number; treasure: number; silverKeys: number;
      goldKey: boolean; deaths: number; floorComplete: boolean; victory: boolean;
  }> }[];
}
```

A replay runs headless: feed byte *t* as the input latch of tick *t*; after the last
byte the run must have satisfied every assert (each checked at its exact tick). The
solution-path tables in 03-levels define the asserts for `f1..f4.replay`.

### 3.2 Macro format (how agents author replays)

Hand-writing per-tick bytes is impractical, so replays are compiled from macro text
(`tests/replay/*.macro`), one command per line:

```
# comment
R 40          # hold RIGHT for 40 ticks
UR 12         # hold UP+RIGHT for 12 ticks
W 30          # wait (no input) 30 ticks
A             # tap ATTACK (1 tick, combined with no movement)
A R 14        # hold ATTACK+RIGHT 14 ticks
Z             # tap INTERACT
assert room=R2 treasure=6   # emit an assert at the current tick
label fork1   # no-op marker for readability
```

Direction letters U D L R combine; a number is a tick count (default 1). The compiler
(`tools/macro-compile.ts`, milestone M2) turns `.macro` into `.replay.json`. Agents
iterate: run headless with `--dump-state-every 30`, read the state trace, adjust the
macro. Determinism guarantees the loop converges.

## 4. State hash

32-bit FNV-1a (`h = 2166136261; h = (h ^ byte) * 16777619 >>> 0`) over the canonical
byte stream: for each field in the fixed order below, little-endian int32 per value.

Order: play-time tick · floor index · current room index · player (x, y, hp, facing,
state id, state timer, iframe timer, invuln timer, knock vx, knock vy) · treasure ·
silver keys · gold key (0/1) · deaths · for each entity in spawn-id order: (type id, x,
y, hp, state id, state timer) · for each spawn telegraph in list order: (type id, col,
row, ticks left) · for each bolt in flight, in spawn order: (x, y) ·
for each trap in document order: phase · for each door:
open state id · for each persistent flag set on this floor (sorted lexicographically):
FNV of its string id · pending wave index · seal state.

`sim.hash()` must be implemented exactly once and used by both the determinism test and
replay `--verify` mode (TESTING.md §3).

## 5. What is deliberately not persisted

No save files. A browser reload starts at the title screen, floor 1. (The audio mute
flag in localStorage is the sole exception, 04-ui §5.) This is a 15-minute game;
checkpoints (01 §6) provide all needed continuity within a session.
